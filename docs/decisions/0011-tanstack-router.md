# 0011: TanStack Router for routing

- **Status:** Accepted
- **Date:** 2026-10-20

## Context

The app shell links to Home, Library and Upload, and later screens add a collection page, clip details
(`/watch/{id}`) and admin pages. The Library keeps its state in the URL, so a search can be bookmarked and
the back button works: search text, sort, filters (uploader, collection, dates) and the cursor for "Load more".
That's several query parameters with types (enums, dates, IDs) that have to be parsed and validated on every
navigation.

## Decision

**TanStack Router, with file-based routes generated by its Vite plugin.**

- Routes are files in `src/routes` (`__root.tsx` is the shell, `index.tsx` is `/`, `library.tsx` is
  `/library`). `@tanstack/router-plugin` writes `src/routeTree.gen.ts` from them on `npm run dev` and `build`.
  The file is committed, so `npm run typecheck` works on a fresh clone, and Prettier and oxlint skip it.
- `main.tsx` registers the router type, so `Link to`, `navigate` and `useSearch` are checked against the
  routes: a link to a route that doesn't exist, or a missing path parameter, is a type error.
- A route's search parameters get a `validateSearch`, which parses them once into a typed object; the Library
  step adds the first one.
- `autoCodeSplitting` loads each route's component on demand.
- The sidebar uses `Link`, which sets `aria-current="page"` on the current route; the nav item's style reads
  that attribute.

## Alternatives considered

- **React Router** (declarative mode). The common default with less to learn, and `NavLink` covers the
  sidebar. Not chosen: search parameters are untyped strings (`URLSearchParams`), so the Library would parse and
  validate its filters by hand, and links aren't checked against the routes.
- **Code-based TanStack routes** (`createRoute` by hand, no plugin). No generated file, but the route tree is
  wired up by hand and there's no automatic code splitting.

## Consequences

- One more generated file next to `schema.d.ts`. It's rewritten when a route file is added, renamed or removed;
  commit it with that change.
- TanStack Query (with openapi-react-query, [0009](0009-generated-api-client.md)) comes from the same family,
  and route loaders can prefetch queries when that's useful.
- oxlint's `only-export-components` rule is off for `src/routes`: a route file exports `Route` and may declare its
  page's components, and `autoCodeSplitting` moves those into a module of their own, which keeps Fast Refresh
  working.
- Pages that need a signed-in user sit in the pathless layout `_authenticated.tsx`, see
  [0012](0012-sign-in-in-the-app.md).
